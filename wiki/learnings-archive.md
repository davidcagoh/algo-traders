## Confirmed (cross-project)

- **LLM-driven sequential strategy refinement gets geometrically trapped.** Both feishu and backtesting independently saw an LLM start from a simple template (SMA, momentum) and refine along that vein for many iterations without exploring orthogonal signal families. The local-minimum is the LLM's prior, not the data. **Mechanistic confirmation:** Simhi et al. 2026 ("Old Habits Die Hard: How Conversational History Geometrically Traps LLMs", arXiv 2603.03308) measures this directly across 3 model families × 6 datasets — once a phenomenon appears in a turn, it persists, with Spearman 0.78 between probabilistic (Markov trace) and geometric (hidden-state angle) measures. **Mitigation hint:** the paper shows the trap *dissolves under topical inconsistency* — randomly shuffling unrelated prompts breaks carryover. Practical implication for strategy ideation: deliberately interleave unrelated topics in any LLM-driven search loop, don't let it stay on one thread for many iterations. See `concepts/multi-objective-search.md` for the structural escape route (move to bounded primitive grammar + Pareto search).
- **Single-objective optimisation overfits at any scale.** Feishu IS-parameter-space exhaustion was reached at modest sweep size; further tuning was flagged as overfitting risk. Backtesting's thin samples (N=6, N=32) make any single-metric ranking noise-dominated.
- **Deflated Sharpe Ratio (López de Prado).** Expected max Sharpe under the null grows with √log(N_configs). Any sweep across more than ~10 configs needs DSR or PBO as a gate, otherwise the winner is structurally noise. Pre-register the gate before running the sweep.
- **DSR strictness is kurtosis-dominated, not N-dominated (refined 2026-05-20).** Original 2026-05-16 finding: DSR flags everything as NOISE at laptop scale. Refined by the feishu port: feishu has N=484 daily wallet obs with bounded non-excess kurtosis (~5.6–6.5) and **DSR cleanly distinguishes all six tested strategies as SIGNAL** (DSR=1.000, SR*=0.156 across the trend_vol family + baselines, sell-open). Backtesting's failure mode was kurtosis 60–340 from few big winners; the `(kurt-1)/4 · SR²` denominator blew up there. **Updated rule:** DSR is binding-meaningful when (excess kurt < ~5) AND (N daily obs > ~250). Below either threshold, demote to humility check. Feishu hits both; backtesting hits neither (yet). Implication for future projects: bounded kurtosis matters more than raw sample size for DSR validity.
- **Six-layer evaluation stack is the principled cross-project frame (2026-05-16).** L1 return → L2 risk-adjusted (Calmar, Sharpe) → L3 sample size (SQN) → L4 multiple-testing (DSR) → L5 tail/path (Ulcer, Martin, skew, kurtosis, CVaR-5%) → L6 portfolio-additive (MDB, corr_to_book). Each layer fixes a failure mode of the one above. Ulcer + Pain catch chronic-underwater curves that MDD misses; portfolio metrics catch near-redundant strategies that look additive only under one weighting scheme. Adopt in both subprojects; feishu can lag on L4–L6 until N is large enough for those layers to be meaningful. Replaces "single-metric leaderboard" wherever it still appears.
- **Diversification is a first-class metric, not an afterthought (2026-05-16).** A strategy is *robustly* diversifying iff Marginal Diversification Benefit (MDB) > 0 under all three weighting schemes: equal-weight, risk-parity (90d trailing vol — the headline), and long-only Markowitz mean-var. Triplet-passing avoids "additive only because of weighting artifacts" false positives. Companion check: pairwise Pearson on per-period returns — strategies correlated > ~0.95 are statistically *one* strategy and only one belongs in any book regardless of how different the implementations look. Applies to any portfolio-of-strategies decision in either subproject.
- **A "smoke test" that runs on the dev machine isn't a smoke test of the deployment (2026-05-21, Track B bring-up).** Track B's local smoke test passed cleanly in ~30s (heartbeat reached, zero errors). Every issue the VPS bring-up hit was invisible to that test: Docker build context too wide (broke `requirements.txt` resolution), bind-mount perms (`chmod 600 as root` blocked the non-root `ftuser` inside the container), `hmmlearn` missing from the Freqtrade base image with no Python 3.14 wheel available, upstream Freqtrade source gitignored in the wrapper repo so a fresh VPS clone didn't materialise it. Each issue is independent of the strategy and would have been caught by *any* full deployment-target run, but none could surface in the dev-machine path because the dev machine already had the venv, the strategy deps, root-owned writable paths, and the upstream Freqtrade source. **Rule:** a "smoke test" only counts as a smoke test if it runs through the actual production execution path (container build + bind mount + non-root runtime + fresh clone). For Track B specifically, that means the next deployment should start with `docker compose build && docker compose up` on a scratch directory, not the local venv. Generalises to any project that ships from a wrapper repo + external image: replicate the deployment shape locally before declaring the harness ready.
- **Audit-pin intent ≠ audit-pin mechanism (2026-05-21, Track B bring-up).** Gate 002 pre-registered "pin Freqtrade by commit SHA `9d0fb9b`" as the audit-fixity mechanism. During VPS bring-up the build path landed on Python 3.14.3 inside the container, for which `hmmlearn` has no prebuilt wheel and the slim image lacks `g++`. Switched to `freqtradeorg/freqtrade:stable` + extension Dockerfile, pinning by **Docker image digest** instead. The binding gate requirement was "no version changes during the 30d window" — that's satisfied identically by either mechanism. **Rule:** when pre-registering an audit pin, write the *invariant* the pin protects (e.g. "no changes during run", "exact behaviour reproducible by a third party"), not just the specific identifier (commit SHA, image tag, package version). When the identifier becomes infeasible mid-deploy, you can swap the mechanism without re-opening the gate as long as the invariant survives. Document the swap in the gate file with the new identifier.
- **VPS deploy keys should be read-only by default; audit artefacts produced on the VPS push from the laptop, not the VPS (2026-05-21, Track B ops).** Track B's deploy key on `algo-traders-live` was set read-only at creation. When `snapshot.sh` on the VPS produced the start-of-clock result file, `git push` from the VPS failed by design — exactly the failure mode we wanted if the VPS were ever compromised. Workflow that survived without weakening the security model: cat the file from VPS, recreate locally, commit + push from the laptop (the actual operator-trusted machine). **Rule:** any project deploying long-running agents to a VPS should pre-decide the audit-write workflow before the deploy: either (a) laptop-mirrors-VPS-output, or (b) a separate scoped write-key restricted to a narrow path glob, or (c) the audit file lives outside the production repo entirely. Don't discover the constraint after the first artefact gets stuck. (a) is the simplest and was used here.

## Data sourcing (cross-project)

- **`ccxt` is the default multi-exchange OHLCV/funding library.** Wraps ~100+ exchanges (Binance, Bybit, OKX, Coinbase, Kraken, Hyperliquid, etc.) with a unified API. Free, no auth for public endpoints. Supports OHLCV, funding rates, order book snapshots, trades. Use this before reaching for anything custom unless an exchange explicitly disables it (Hyperliquid OHLCV via Freqtrade is one such case — see `freqtrade-experiment/hmm-slope-experiment/research/analysis/reports/2026-04-24-decision-002`).
- **Free historical funding rate JSON** is published by Binance and Bybit going back years, no auth. Cheapest path to test the CEX→DEX funding lead-lag hypothesis (`freqtrade-experiment/hmm-slope-experiment/research/analysis/reports/learnings.md` open #6).
- **CEX OHLCV as proxy for pre-Hyperliquid history.** Binance BTC perps go back to ~2019; Hyperliquid only ~2023. Use CEX history to *train* regime detectors and HMMs across more cycles. Do **not** use CEX history to *evaluate* a Hyperliquid strategy — microstructure (fee, funding mechanism, liquidity, slippage) differs.
- **`yfinance`** — fine for daily/hourly equities + ETFs + spot crypto (BTC-USD). Useless for perps, funding, intraday <1h, or anything Hyperliquid-specific. Reach for it only when you want equity/macro covariates (SPY, DXY, VIX) as regime inputs to a crypto model.
- **`Scrapling`** (and other scrapers) — wrong tool for market data. Bookmark for non-API sources only (CryptoQuant dashboards, Coinglass heatmaps, on-chain UI-only metrics). Default to ccxt + direct exchange APIs first.
- **Hyperliquid S3 L2 book snapshots** (`s3://hyperliquid-archive/market_data/`) — free, public, massive. Only worth ingesting when the SaR slippage proxy hypothesis (`freqtrade-experiment/hmm-slope-experiment/research/analysis/reports/learnings.md` open #8) becomes the active experiment.

## Open hypotheses (cross-project)

1. **Multi-objective Pareto search beats single-metric max** when objectives are negatively correlated under noise (Calmar-bull, Calmar-bear, ulcer, turnover-adjusted PF, OOS-stability). Inspired by `concepts/divergence_portfolio_theory.md` — same logic as α-portfolio for distribution fitting.
   - **Test:** scaffold an NSGA-II run on a small primitive grammar (~6 signal families × 2–3 hyperparams) once a subproject has enough independent trades per fold.

2. **Strategy retirement / kill criteria are missing from both subprojects.** Per Dan Davies (ex-quant, in the comment thread of Leek 2025): *"quant funds survive in the long term because of fundamentally non-quantitative attributes of their managers; it is a very rare person indeed [who] combines the common sense to turn the model off when it is breaking down, with self-discipline to resist the temptation to tinker."* Neither feishu's `trend_vol_v4` nor backtesting's `SmaRegime180` has a documented condition under which it would be retired. This is the real survival mechanism — risk *management*, not signal *quality*.
   - **Test:** before any strategy graduates from leaderboard to paper-trading, write a retirement rule of the form: "kill if rolling-90d Calmar drops below X, or if drawdown exceeds Y% of historical max DD, or if regime indicator Z flips for N consecutive bars."
   - **Open methodology:** written up as [`kill-criteria.md`](concepts/kill-criteria.md) (2026-05-16) — cross-project frame covering the four canonical axes, family-specific kill rules, Davies–Ravagnani continuous shrinkage, calibration discipline, revise-vs-kill review.
   - **Supporting evidence (2026-05-09 feishu pull):** Pang & Lin 2025 (5-state correlation regime classifier on Chinese A-shares) + Ravagnani et al. 2026 (`h_robust = h_standard × (1 − δ/σ²)`, continuous shrinkage replacing binary skip rules) both provide concrete *mechanism templates* for kill-rule construction. Ravagnani in particular suggests the right form is **continuous shrinkage of position size** as forecast-error/vol ratio rises, not a binary on/off switch. When the first kill rule is written, prefer continuous shrinkage over hard cutoffs.
   - **First concrete kill rule drafted (2026-05-10):** `freqtrade-experiment/hmm-slope-experiment/research/analysis/reports/2026-05-10-decision-004-kill-criteria-sma-regime-180.md`. Combines hard-kill triggers (MDD > 5.5% = 3× backtest, six straight stops, rolling 365d return ≤ 0 for 30d, walk-forward Calmar < 2) with a Davies–Ravagnani continuous-shrinkage formula that ties live size to rolling 180d PF × Calmar × bull/bear ratio. Pattern is exportable to feishu's `trend_vol_v4` once cross-cycle validation data exists. Generic methodology now written up at [`kill-criteria.md`](concepts/kill-criteria.md) (2026-05-16), synthesising from decisions 004/006/007/008.

## Ruled out (cross-project)

- **Read the official scoring spec early; absolute-Score sweeps may be misaligned with what the venue actually scores (2026-05-20, feishu).** For two months feishu's leaderboard and signal selection optimised against the raw scalarization `0.45·CAGR + 0.30·Sharpe + 0.25·(−MDD)`. PDF §7.1 (Feishu_Quant_Competition.pdf, read 2026-05-20) defines the actual competition Score as the same coefficients applied to **percentile ranks across submitting teams**: `0.45·CAGR_pct + 0.30·SR_pct + 0.25·MDD_pct`. The two formulas can disagree about which strategy wins, because percentile-ranking rewards *extreme* component values more than balanced ones — a low-MDD low-CAGR strategy can beat a balanced one even if the raw weighted sum is lower, as long as competitors' MDD distribution is wider than their CAGR distribution. **Generalisation:** any time a venue scores via percentile, rank, or normalisation, the IS scalarization is a sub-optimal optimisation target by construction. **Operational rule:** for any sponsored competition or benchmark, locate the precise scoring function and write a sentence-level summary into the project wiki **before** any signal sweep. The L5 tail-shape layer becomes more important under percentile scoring because honest Sharpe (lower kurtosis) is more likely to percentile-rank reliably on OOS than fat-tailed Sharpe at the same raw value.
- **Orthogonality is necessary but not sufficient for MDB-positive contribution (2026-05-20, feishu).** `clustering_reversal` (Jiao & Zheng Nov 2025 mechanism, long-only adaptation at 5d horizon) had pairwise correlation 0.054 with `trend_vol_v4` — structurally as far from low_vol as you can get. But standalone CAGR was −44.29% on full IS, MDD 69.97%, kurt +17.59. MDB-eq/rp/mv all deeply negative because under any weighting, adding losing PnL to winning PnL hurts the book. MDB-rp's risk-parity weighting amplifies the harm — low-vol losing strategies get higher inverse-vol weight. **Generalisation:** the MDB gate fires sensibly even on orthogonal candidates only if the candidate's standalone Sharpe is positive. For negative-Sharpe orthogonal candidates, the MDB gate is dominated by Sharpe arithmetic, not by diversification benefit. **Practical filter:** require Gate-1 (positive standalone CAGR on both tuning and held-out) before computing MDB at all. See `feishu/analysis/reports/2026-04-24-decision-002-kill-criteria-clustering-reversal.md` and `feishu/analysis/reports/2026-05-20-clustering-reversal-validation.md`.
- **The multi-day-horizon hypothesis does not rescue reversal from feishu's execution-gap problem (2026-05-20).** The original reversal-fails-because-of-overnight-gap finding (`wiki/_index.md` 2026-04-10) used 1d signals. Extending to 5d cluster-relative reversal made things *worse* (CAGR −44% vs ~−54% for the simpler reversal, but on a different selection — comparable in magnitude). Cluster-relative 5d underperformers are crashing stocks, not mean-reverting candidates. Buying them at `vwap_0930_0935` continues the crash through the buy window. **Rule:** any reversal-shaped long-only signal at the `vwap_0930_0935` execution point is presumptively dead in feishu; future reversal hypotheses must justify why their *specific* mechanism breaks the falling-knife pattern, not just appeal to "longer horizon."
- **Held-out windows that don't span the strategy's design regime produce passing-but-uninformative gates (2026-05-20, live).** SGX trend_vol hedged passed gate 004 on held-out 2023-2026, but the held-out window was bull-only (buy & hold +16.91% CAGR, MDD 11.1%). The hedge's drawdown-protection contribution was therefore untested. A cross-cycle stress on HSI 2014-2024 (containing the 2021-2023 HK bear) caught the gap: the hedge cut MDD only 10% relative (vs 30% threshold), failed 4 of 5 gate-006 criteria, was falsified. **Generalisation:** pre-register the *regime characteristics* the held-out window should contain, not just dates. A calendar-only held-out (feishu's 2026-06→12, backtesting's 30d dry-run windows) inherits whatever regime the calendar happens to deliver. If the calendar window is monotone (all bull or all bear), the gate becomes "did the strategy clear a tradability bar in this regime" rather than "is the strategy tradeable across regimes." Both are valid tests but they're different tests. See `wiki/artifacts/equity-trend-vol/decisions/006-cross-cycle-stress-test.md` and `wiki/artifacts/equity-trend-vol/results/2026-05-20-cross-cycle-hsi-BINDING.md`.
- **Mechanism transplants are venue-sensitive at the SELECTION layer, not just the parameter layer (2026-05-20, live).** The trend_vol_v4 low-vol selection mechanism produced Sharpe 1.20 (hedged, tuning) on SGX, Sharpe 0.47 on HSI, and Sharpe 0.46 on IDX with the *same* hedge, *same* low-vol formula, *same* liquidity filter — only the universe differs. The selection ranking that picks winners on A-shares + SGX picks Sharpe-below-buy-and-hold on HSI even at frozen params. Parameter tuning (top_n, rebalance period) was the obvious knob and isn't enough. **Generalisation:** when porting a mechanism across venues, the *selection logic* must be venue-validated *before* parameter tuning. A signal that works on one venue's cross-section may produce anti-signal on another's. Cross-cycle stress on a third venue catches this where parameter sweeps don't.
- **Hedge layers can shift tail-risk shape rather than reduce tail risk (2026-05-20, live).** On HSI cross-cycle, the SMA hedge cut MDD by 10% (47.2% → 42.5%) but *raised* excess kurtosis from +4.6 to +14.9. The hedge's flat-then-back-in transitions produced discrete return jumps that fattened the distribution's tails even as the worst single-day return improved. The mechanism that's supposed to reduce tail risk is *creating* a different shape of tail risk. **Generalisation:** any L5 tail-shape gate must measure skew and excess kurtosis *separately* from MDD. A hedge that passes "lower MDD" can fail "lower fat-tailedness" and the latter is more relevant for live capital because regime transitions produce the discrete jumps. Practical rule: pre-register a "kurt_hedged ≤ kurt_unhedged" sub-gate alongside MDD reduction whenever a regime-gate or hedge mechanism is introduced.
- **Threshold-style perturbations of an already-tuned strategy are particularly vulnerable to held-out collapse (2026-05-20, Feishu competition).** trend_vol_v6 = v5 logic at fixed N=20 (regime-conditional threshold without regime-breadth-expansion). Looked promising in IS (tuning ΔScore +0.0305 vs v4 on D001–D400), collapsed on held-out (held-out ΔScore −0.0475 on D401–D484). **Mechanism:** the perturbation's effect (stricter threshold on bull days) was concentrated in tuning-window bull periods; held-out had no bull days, so the perturbation showed *only* its harm (slightly lower CAGR), not its benefit. **Generalisation:** any single-axis hyperparameter perturbation should be evaluated on a held-out window that covers the *regime in which the perturbation has effect*, not on an arbitrary held-out window. Pre-registered ±0.01 ACCEPT band + cross-cycle gate together correctly caught the false signal. See `feishu-competition/analysis/reports/decisions/001-kill-criteria-trend-vol-v6.md` and `feishu-competition/analysis/reports/2026-05-20-trend-vol-v6-validation.md`.
